# EUVCRAFT 0.7.1 — Alpha

## Changes

- Fix the EUV scanner/light-source component placement crash and restore formed-state visuals and cleanup.
- Fix light-source member placement orientation and scanner calibration buttons missing on first open.
- Separate physical beamline connection from exposure reservation and show source readiness and linked scanner coordinates.
- Add a required source Pulse Control Module and separate Calibration Panel with droplet phase, main-pulse delay and pulse-amplitude tuning, paid FE/hydrogen/tin-credit tests and saved acceptance.
- Freeze the accepted source yield factor and installation identity once per lot; prevent active-source retuning or source swapping for better results.
- Upgrade NeoForge to 26.3.0.99, resolving WorldEdit 7.4.6's previous loader-version rejection.

## Install and upgrade

Use Java 25, Minecraft 26.3 and NeoForge **26.3.0.99** (tested). Install lithmod-0.7.1.jar with Arcforge 2.8.1+26.3 and Encoded Logistics 1.5.0+26.3 on client and server. WorldEdit is optional. Do not install the compile-only arcforge-api-1.2.0+26.3.jar.

Existing T7 sources need one Pulse Control Module and one Source Calibration Panel in unused middle-layer positions of their existing 3x3x5 structure. Calibrate the source before processing. Finish or abort in-flight T7 runs before updating; older active runs have no saved source-calibration binding. Existing completed FOUPs and lower-tier progression retain their data. Back up worlds before updating.

## Verification and limitations

Verified 1,424 unit tests, all 353 project in-game cases (349 prior cases retained), fixture-disabled shipping with WorldEdit 7.4.6 loaded, generated resources, core/JAR checks and zero-cost Beam review. The JAR and SHA256SUMS.txt accompany the release. This remains an Alpha prerelease; the new graphical calibration flow and balance require player playtesting. No T8, recycler or Encoded Logistics hardware-server implementation is included.
