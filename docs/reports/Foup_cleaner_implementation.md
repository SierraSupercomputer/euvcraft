# FOUP cleaner implementation

Owner accepted the cleanroom walkthrough, authorized a standalone cleaner and confirmed one Wafer Scrap per discarded wafer. Added one early-game FE/ordinary-water machine with explicit Discard & Clean, five separated slots and editable JSON costs/recipe. No cleanroom, calibration, chip package or UPW requirement. Existing worlds/FOUP serialization remain compatible.

Water reserves once; tick energy and duration freeze at admission. Insufficient FE pauses transactionally; finished blocked outputs charge no further energy. Destructive completion replaces only the physical input with a fresh empty lot, preserving the carrier item/capacity/custom name. Accepted-input snapshots are fingerprints, never additional owned carriers. Scrap emits into bounded stacks and pending waste persists. Before disposal, break returns original wafers with no service refund. After disposal, break drops the one empty carrier plus emitted/pending waste. Native inventories are locked during work; button requires the actual valid menu. Fluid/FE capability lenses reject stale owners and fluid input uses the native transaction framework on all faces. No automatic item input or hidden-roll selection.

Two scoped free Nemotron drafts supplied the pure helper/tests and deterministic asset generator. Coordinator supplied native integration, resource censuses, native cases and draft repairs. Original domain tests invented a CleanroomExposure API and contradicted empty-carrier rejection; repaired before acceptance. Scores and zero-cost evidence remain in the coordinator workspace. Beam's read-only static review approved the frozen implementation without claiming execution.

Initial execution:1151 units pass after those repairs;11 native cleaner cases pass for admission, both carrier variants/completed lots/custom name, exact costs, insufficient-FE rollback/resume, bucket conservation, real transactional water/stale capabilities, blocked outputs, multi-stack waste, paid-progress reload, pending-waste reload, pre/post-disposal break and changed-input cancellation. Unit tests cover prepared/exposed lot state reset. The final candidate receives the full retained native suite, shipping fixture check, jar inspection, eight nonwriting generators and client GUI inspection; final receipts are maintained by the coordinator. See ../manual-walkthrough-foup-cleaner.md for owner checks.

No Contaminated FOUP producer, T6/T7 abort/repair consequences, recycling, item automation or future-tier content is implemented. Costs are initial coordinator defaults:200 ticks,20FE/t,1000mB water,16000mB tank,40000FE buffer; scrap_per_wafer defaults1. No online/world installation is performed by publication.

Initial full candidate execution retained967 cases but failed two assertions: the exact recipe-less item inventory omitted the deliberately machine-produced wafer_scrap, and the existing diagnostic drop fixture queried newly spawned entities in the same tick. The final fixture includes the exact new item and checks one remaining paper/current owner/actual removal, then requires exactly one drop after one server tick. It does not alter scanner production code or relax the drop count; a missing drop still fails. The failed raw run is preserved and the full candidate is rerun.
